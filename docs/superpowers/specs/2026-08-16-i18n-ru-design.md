# Локализация RU/EN — дизайн

**Дата:** 2026-08-16
**Проект:** about (персональный сайт-портфолио)
**Объём:** добавить русскую локаль с переключателем языка; английская версия остаётся дефолтной

---

## Цели

- Полный перевод на русский: интерфейс, главная, таймлайн (18 точек), резюме (8 мест работы, 12 навыков)
- Переключатель языка в шапке, язык отражается в URL и переживает перезагрузку
- Русский текст рендерится шрифтами с кириллицей, а не системным фолбэком
- Неполный перевод обнаруживается на сборке, а не в проде

## Вне рамок

- Правка грамматики английских текстовок (обсуждалась, вынесена отдельно)
- `src/Components/CV_NO_DESIGN/`, `src/Pages/Main/articles.tsx` — мёртвый код, не подключён ни к одной странице
- Страница mind-map — единственный её текст это названия технологий (HTML, CSS, JS, GIT, React), переводить нечего
- `src/shared/CV.pdf`
- Телеграм-боты (`botRougue/`), `ton.js`, `start_db.sh`
- Удаление артефактов CRA (`src/App.tsx`, `src/index.tsx`, `build/`, `src/index.css`)

## Принятые решения

| Вопрос | Решение |
|---|---|
| Объём перевода | Всё, включая таймлайн и резюме |
| Роутинг | Встроенный i18n Next.js, префикс `/ru`, автоопределение языка выключено |
| Шрифты | Разные по локали; EN сохраняет текущий вид |
| Английские тексты | Переносятся дословно, без правок |
| Тон русской версии | На «вы», деловой |
| Хранение контента | Инварианты отдельно, по-локальные `.tsx`-словари под общим интерфейсом |

## Архитектура

### Роутинг

`next.config.js`:

```js
i18n: {
  locales: ['en', 'ru'],
  defaultLocale: 'en',
  localeDetection: false,
}
```

| Маршрут | EN | RU |
|---|---|---|
| Главная | `/` | `/ru` |
| Таймлайн | `/history` | `/ru/history` |
| Резюме | `/cv` | `/ru/cv` |

Существующие английские адреса не меняются. Автоопределение выключено намеренно: рекрутёр с русской локалью браузера должен попадать на английскую версию.

Все страницы остаются статическими. Next при наличии `i18n` пререндерит каждый маршрут для каждой локали; `getStaticProps` не требуется, потому что словарь выбирается при рендере по `router.locale`, доступному и на сервере.

### Структура файлов

```
src/i18n/
├── types.ts            # Locale, Dictionary и вложенные интерфейсы
├── structure.ts        # инварианты: id, годы, иконки, URL, логотипы, проценты, позиции
├── useTranslation.ts   # хук выбора словаря
├── index.ts            # dictionaries = { en, ru }
├── en/
│   ├── ui.ts
│   ├── main.tsx
│   ├── roadmap.tsx
│   └── cv.tsx
└── ru/
    ├── ui.ts
    ├── main.tsx
    ├── roadmap.tsx
    └── cv.tsx
```

Разбиение по секциям, а не один файл на локаль: единый словарь вырастает до ~15 КБ и перестаёт читаться.

### Разделение инвариантов и текста

`structure.ts` содержит всё, что одинаково в обеих локалях и потому не должно дублироваться:

- **Таймлайн:** порядок точек, `id`, год, MUI-иконка, дефолтные `plotPosition` / `goalsPosition`
- **Резюме:** контакты (телефон, email, telegram, linkedin), `id` и `strength` навыков, `id`, даты, логотипы и URL компаний
- **Высоты блоков** резюме (`person.height`, `education.height`) и функция `numberOfYears`

Словари содержат только текст.

### Типы

```ts
// src/i18n/types.ts
import type { ReactNode } from 'react'

export type Locale = 'en' | 'ru'

export interface UiText {
  nav: { main: string; story: string; cv: string }
  personName: string     // «Suntsev Sergey» / «Сергей Сунцев»
  jobTitle: string
  calendlyCta: string
  cv: {
    personalInfo: string
    skills: string
    education: string
    experience: string
    phone: string
    email: string
    telegram: string
    linkedin: string
  }
}

export interface MainText {
  greeting: string       // печатается посимвольно через usePrintText
  description: ReactNode // содержит ссылки на Instagram и Github
}

export interface GoalItem {
  name: string
  note?: string          // «(base level)» — пояснение вне подсветки
}

export interface RoadmapText {
  plot: ReactNode        // может содержать инлайн-ссылку
  goalsLabel: string     // «New skills» / «Goals»
  goals: GoalItem[]
  plotPosition?: string  // переопределение позиции под длину текста локали
  goalsPosition?: string
}

export interface CvText {
  about: string
  education: { name: string; description: string; gradeLevel: string }
  skills: Record<SkillId, { name: string; description: string }>
  experience: Record<JobId, {
    jobName: string
    company: ReactNode
    description: ReactNode
  }>
}

export interface Dictionary {
  ui: UiText
  main: MainText
  roadmap: Record<RoadmapId, RoadmapText>
  cv: CvText
}
```

`RoadmapId`, `SkillId`, `JobId` — union-типы, выведенные из константных кортежей в `structure.ts`:

```ts
export const ROADMAP_IDS = ['first-code-2011', 'web-php-2013', ...] as const
export type RoadmapId = typeof ROADMAP_IDS[number]
```

**Это и есть гарантия полноты перевода.** `Record<RoadmapId, RoadmapText>` требует все ключи: пропущенная точка таймлайна или место работы — ошибка типа на `next build`, а не пустой блок на странице. Тестового раннера в проекте нет и настраивать его ради этого незачем — компилятор закрывает основной риск бесплатно.

`plotPosition` / `goalsPosition` в словаре — сознательный компромисс. Это вёрстка, а не текст, но сдвиги подогнаны под длину конкретной фразы, а русский обычно длиннее на 10–15%. Дефолт живёт в `structure.ts`, переопределение в словаре — только там, где реально понадобилось.

### Хук

```ts
// src/i18n/useTranslation.ts
export const useTranslation = (): Dictionary => {
  const { locale } = useRouter()
  return dictionaries[locale as Locale] ?? dictionaries.en
}
```

Библиотека не подключается: для двух локалей без плюрализации, интерполяции и форматирования дат `next-intl` — лишний слой конфигурации.

### Шрифты

Кириллицы нет только в двух подключённых шрифтах:

| Шрифт | Глифов | Кириллица | Где используется |
|---|---|---|---|
| Modeseven | 101 | нет | глобальный дефолт (`src/styles.ts:78`) |
| SuperLegend | 205 | нет | приветствие (`src/Pages/Main/styles.ts:26`) |
| PressStart | 656 | есть | подключён, не используется |
| RobotoSlab | 902 | есть | резюме, таймлайн, mind-map |

Резюме, таймлайн и mind-map уже используют RobotoSlab и по-русски отрендерятся без изменений. Проблема ограничена глобальным дефолтом и приветствием.

Вводятся семантические CSS-переменные вместо прямых ссылок на шрифт:

| Переменная | EN | RU |
|---|---|---|
| `--font-display` | SuperLegend | PressStart |
| `--font-body` | Modeseven | RobotoSlab |

`pages/_app.tsx` вешает на `Layout` класс локали, переопределяющий эти две переменные. `src/styles.ts:78` и `src/Pages/Main/styles.ts:26` переходят на семантические имена. Компоненты, уже ссылающиеся на `--font-roboto-slab`, не трогаются.

PressStart существенно шире SuperLegend, поэтому кегль приветствия (сейчас 32px, 25px на мобильном) для русской локали подбирается отдельно.

Переключатель использует `<Link href={asPath} locale="ru">` — Next сохраняет текущую страницу при смене языка.

`goals` перестаёт быть JSX: 18 полей вида `<span>New skills: <GoalPoint>OOP</GoalPoint>, ...</span>` становятся `GoalItem[]`, а разметка переезжает в `StoryPoint.tsx`. Инлайн-ссылки в `plot` (`project-pro.do.am`, `webschool.pspu.ru`) и списки `<ul><li>` в описаниях работы остаются JSX прямо в словаре — их немного, а рантайм-парсер markdown ради них не оправдан.

## Дефекты, исправляемые попутно

Оба обнаружены при разборе и блокируют работу:

1. **Дублирующийся `id` в таймлайне.** Точек 18, уникальных `id` 17 — `"the ten time"` встречается дважды. Сейчас это баг: `openedPointList.includes(item.id)` в `RoadMap/index.tsx:67` раскрывает обе точки одновременно. Для `Record<RoadmapId, RoadmapText>` дубль означал бы потерю одного из двух текстов. Все `id` переименовываются в осмысленные слаги (`the forth half one time` → `first-job-2016`); они используются только как React-ключ и признак раскрытия, на URL не влияют.

2. **`<Html lang="ru">` на английском сайте** (`pages/_document.tsx:27`) — становится динамическим.

Отдельно фиксируется, но не чинится: `styles/globals.css:7` ссылается на `'Legend', 'ModeSeven'` — имена CRA-эпохи, которых больше не существует после перехода на `next/font`. Бейдж Calendly уже сейчас падает на Roboto. Правка не относится к локализации; выношу в бэклог.

## Проверка

1. `next build` собирает обе локали — по статической странице на маршрут на локаль
2. Заведомо неполный словарь (временно удалить ключ) валит сборку с ошибкой типа
3. Ручной прогон шести маршрутов: `/`, `/ru`, `/cv`, `/ru/cv`, `/history`, `/ru/history`
4. Переключатель сохраняет текущую страницу при смене языка
5. Кириллица на `/ru` рендерится PressStart и RobotoSlab, а не системным фолбэком — проверяется в DevTools по вычисленному `font-family`
6. `/ru/history`: удлинившийся русский текст не наезжает на соседние точки таймлайна и не выходит за границы блока
7. `/ru`: приветствие печатается посимвольно без обрезки и переносов, кегль подобран под PressStart
8. `<html lang>` соответствует локали на обеих версиях

## Риски

- **Ширина PressStart на приветствии.** Может потребовать не только кегля, но и переноса строки. Если результат окажется неприемлемым, запасной вариант — RobotoSlab для русского приветствия, с потерей пиксельной стилистики на главной.
- **Длина русского текста в таймлайне.** Позиции подогнаны под английский; переопределения в словаре предусмотрены, но объём подгонки выяснится только на живой вёрстке.
- **Расхождение качества версий.** Английский переносится дословно с существующими грамматическими ошибками, русский пишется с нуля и будет чище. Это осознанное следствие решения не трогать английский.
- **Рассинхрон версии Next.** `package.json` фиксирует `16.2.5`, установлено `16.1.6`. На поддержку `i18n` не влияет (проверено в типах установленной версии), но сборка идёт против 16.1.6.
